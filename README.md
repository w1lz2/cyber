# Мониторинг записи в посольство Молдовы (Reservio) → Telegram

Бот **каждую минуту** берёт все свободные окна по услуге «Изготовление паспорта (загран)»
напрямую из API сайта записи и присылает в Telegram **только новые**:
- окна, освободившиеся после чьей-то отмены;
- новые дни, открывшиеся для записи (запись открыта на 30 дней вперёд).

Кнопки в Telegram:
- **🔍 Проверить сейчас** — свежая проверка и все свободные окна прямо сейчас (новые помечены 🆕);
- **ℹ️ Статус** — работает ли мониторинг, когда была последняя проверка.

Также есть команды `/check` и `/status` в меню бота и кнопки «📝 Записаться» под сообщениями.

Работает бесплатно на серверах GitHub — ваш компьютер не нужен.

## Настройка (≈5 минут)

### 1. Telegram-бот
1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя → получите **токен** (вида `123456:ABC...`).
2. Найдите своего бота и нажмите **Start** (иначе он не сможет вам писать).
3. Откройте **@userinfobot** → он пришлёт ваш **Id** (число).

### 2. Секреты в репозитории
**Settings → Secrets and variables → Actions → New repository secret**:
- `TG_TOKEN` — токен бота
- `TG_CHAT_ID` — ваш Id (можно несколько через запятую, например `111111,222222`, —
  уведомления придут всем, и кнопки будут работать у всех)

### 3. Запуск
**Actions** → (если попросит — включите workflows) → **Мониторинг записи** → **Run workflow**.
Через 1–2 минуты в Telegram придёт «✅ Мониторинг запущен» со сводкой свободных сейчас окон
и кнопками внизу. Дальше всё работает само.

> Если секреты ещё не добавлены, запуск делает одну пробную проверку и завершается —
> в логе видно, отвечает ли сайт с серверов GitHub.

## Пример уведомления
```
🟢 Новые свободные окна (33) — Изготовление паспорта (загран)

👤 Владимир Руснак
  вт 17.11: 10:15
👤 Дойна Гайтур
  пт 27.11 🆕 новый день: 32 окна (08:00–15:45)
       [🔍 Все окна]  [📝 Записаться]
```

## Дополнительно
- **Только определённые сотрудники:** Settings → Secrets and variables → Actions → вкладка **Variables** →
  `STAFF` = `Владимир Руснак, Дойна Гайтур` (по умолчанию — все, кто ведёт услугу).
- **Другая услуга:** переменная `SERVICE_ID`. Список ID услуг печатается в логе первого запуска
  (Actions → запуск → «Проверка свободных окон»).
- Если сайт не отвечает 3 проверки подряд — бот предупредит, а когда заработает — напишет.
- **Остановить мониторинг:** Actions → Мониторинг записи → «⋯» → **Disable workflow**
  (и отменить текущий запуск).

## Как устроено расписание
Один запуск в GitHub Actions работает ~5,5 часа: проверяет сайт каждую минуту, а между проверками
ждёт нажатий кнопок в Telegram и отвечает сразу. Расписание (каждые 20 минут) только ставит следующий
запуск в очередь — он стартует сразу, как закончится текущий (перерыв ≈ 1 минута; нажатия за это
время бот выполнит сразу после старта). Во вкладке Actions поэтому всегда один запуск «в работе»
(жёлтый), а лишние из очереди отменяются (серые) — это нормально.
Если в репозитории 60 дней нет изменений, GitHub приостанавливает расписание (пришлёт письмо,
включается одной кнопкой).

## Вариант: свой сервер (VPS) или Railway
```bash
pip install requests
export TG_TOKEN=... TG_CHAT_ID=...
nohup python3 monitor.py --loop > monitor.log 2>&1 &
```
Для Railway есть `railway.json` (запускает `python -u monitor.py --loop`), переменные `TG_TOKEN` и
`TG_CHAT_ID` задаются в настройках сервиса.
**Бот должен работать в одном месте:** если запущен VPS/Railway — отключите workflow на GitHub,
иначе уведомления будут дублироваться, а кнопки — отвечать через раз.
